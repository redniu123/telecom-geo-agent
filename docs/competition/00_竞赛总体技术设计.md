# 面向 QGIS 的通信线路参数化智能设计、冲突校核与标准图纸自动生成系统

> 状态：竞赛版实施约束（P0 不变）
> 对应赛题：XA-202610，子赛题 1
> 数据边界：离线、公开 OSM 背景 + 派生候选拓扑 + 合成通信属性
> 成果声明：竞赛样例，不是正式施工图，不代表现实运营商网络

## 1. 问题与目标

传统通信线路设计需要在 GIS 中反复加载数据、手工选线、检查容量/状态冲突、重画路线并整理材料清单。竞赛版把这条过程收敛为一个可复算链：

```text
结构化参数录入
→ 参数预览与确认
→ 约束前候选路线
→ 独立冲突校核
→ 一次有界禁用与重规划
→ 最终校核
→ 路线/BOM/事件证据
→ QGIS 图层组与标准图纸 PDF
```

目标不是替代勘察、概预算、设计审查或施工图签章，而是在明确数据边界的竞赛样例中证明：参数化输入、可解释冲突校核、确定性修复、标准化地图交付可以真实运行和复算。

## 2. 与冻结 P0 的关系

- `data/demo/`、`telecom_core/`、`agent/`、`run_demo.py` 和 P0 测试保持原行为。
- 竞赛版使用独立的 `competition/`、`data/competition/`、`outputs/competition/`、`tests/competition/`。
- 路由、三条 P0 校核规则和 BOM 仍调用唯一的 `telecom_core`；竞赛层只增加结构化入口、用户禁用约束、数据适配、证据输出和 QGIS 展示。
- 无模型、无 API Key、无在线服务。所谓“智能”限定为参数驱动、确定性最短路、规则校核、可解释修复与自动制图。

## 3. 数据分层

| 数据层 | 分类 | 允许的结论 |
|---|---|---|
| 道路、建筑、水体、用地、铁路 | `public_real` / `public_real_derived_subset` | 只说明公开地理背景与几何来源 |
| 两个端点 | `synthetic` | 只用于竞赛路线起终点 |
| 候选通道拓扑 | `derived_from_public_road_geometry` | 只说明沿公开道路几何构造的候选走廊 |
| 通道类型、容量、占用、状态、成本 | `synthetic` | 只用于规则和重规划演示 |
| 路线、问题、BOM、图纸 | `derived_competition_output` | 只针对本数据包和本次参数成立 |

公开数据来自 OpenStreetMap/Overpass，保留 `© OpenStreetMap contributors` 与 ODbL 1.0。任何公开发布前仍需人工复核当时的 OSMF 署名指南、仓库分发方式与 share-alike 义务。

## 4. 数据构建

`scripts/build_competition_dataset.py` 对 staging 只读：

1. 校验 `source_manifest.json`、选定 GeoJSON 和原始下载文件的 SHA-256、要素数与 CRS；
2. 拒绝命中联系方式、军事、电力、通信或政府类敏感标签键的数据；
3. 从公开道路坐标图中找出两个端点间两条边不重合路径；
4. 把两条路径重新编号成 79 段候选通道，避免把 OSM 道路误称为真实管道；
5. 仅保留路线范围内的公开背景子集；若 OSM way Polygon 环首尾未闭合，只在派生副本中补回首点，并记录修复环数量；
6. 生成仓库内 manifest，逐文件记录分类、来源、哈希、要素数和生成规则。

插件运行不依赖 staging 绝对路径；staging 仅用于可重复重建与来源审计。

## 5. 参数合同与 fail-closed

结构化参数包括：数据集、场景、起点、终点、光缆芯数、是否优先已有管道、显式禁用资产。执行前必须先预览，再由用户点击确认；任一字段变化都会使旧确认失效。

“优先已有管道”勾选时使用 `长度 × 相对成本系数`；取消勾选时竞赛适配层把候选边权重统一为纯长度。该转换只作用于当前运行内存中的副本，不修改公开/派生数据，也不修改冻结 P0 路由器。

拒绝执行的条件包括：

- 场景或数据集未知；
- 起终点不存在、相同或不可用；
- 芯数不是 1–576 的整数；
- 禁用资产不存在或格式非法；
- 确认摘要的指纹与当前字段不一致；
- 规划无路、校核含不可修复错误、一次修复后仍失败；
- completed 状态缺少最终路线、最终 PASS 或 BOM。

## 6. 三个可复算场景

| 场景 | 约束前候选 | 首次校核 | 修复/结果 |
|---|---|---|---|
| `capacity_reroute` | 较短的走廊 1 | 合成容量段剩余 16 芯，小于 24 芯 | 禁用该段，经走廊 2，最终 PASS |
| `forbidden_reroute` | 较短的走廊 1 | 命中用户/场景显式禁用段 | 禁用该段，经走廊 2，最终 PASS |
| `no_path` | 较短的走廊 1 | 两条走廊各有一个显式禁用断点 | 应用约束后无路，明确 FAIL，不生成 BOM/正式最终路线 |

第一次路线是“约束前候选路线”，不表示可施工或已批准。只有最终独立校核通过后才生成 BOM。

## 7. QGIS 展示与生命周期

插件只管理带自有 custom property 的图层和图层组。稳定层序为：背景用地、建筑、水体、铁路、道路、候选通道、机房、基站、约束前候选路线、问题、最终路线。默认突出最终路线和问题；背景低饱和。标签只显示合成站点/资产 ID，不显示地址或现实设施名称。

加载使用插件运行时相对路径；切换场景先释放旧 OGR 数据源；卸载只清理插件自有菜单、工具栏、Dock、图层与布局，不触碰用户已有项目对象。地图缩放到本次候选/最终路线范围。

## 8. 标准图纸

QGIS Print Layout（或在无 GUI 的真实 PyQGIS smoke 中创建的等价 Layout）输出 A3/A4 PDF，至少包含：

- 标题、场景 ID、参数摘要与结果状态；
- 地图、图例、比例尺、北箭头；
- 起终点、候选通道、约束前路线、最终路线、问题标注；
- 路线长度、相对成本、BOM 摘要；
- 数据集版本、公开数据署名、真实/派生/合成边界；
- “竞赛样例 / 非正式施工图”。

导出后必须使用独立 PDF 工具重读页数/文本并渲染成图片目视检查，不能以导出 API 返回成功代替版面验收。

## 9. 可验证指标

自动遥测只记录系统实际运行的单调时钟耗时、事件数、状态和产物哈希。人工基线模板由 Quimer 实测填写；在人工数据缺失时，计算脚本必须输出 `pending_human_baseline`，不得编造效率提升、用户数、点击数或人工工时。

指标公式：

```text
效率提升率 = (人工基线秒数 - 系统秒数) / 人工基线秒数 × 100%
操作减少率 = (人工基线操作数 - 系统确认后操作数) / 人工基线操作数 × 100%
```

赛题门槛判定为：效率提升率 `>= 30%` 或操作减少率 `> 50%`。三场景的系统侧实测可以自动完成；人工对照和最终门槛结论必须等待真实填写。

## 10. 验证层次

1. 普通 Python：参数、数据审计、三场景事实、输出内容、指标 fail-closed、打包清单。
2. 可重复 CLI：三场景落盘、相同输入核心 JSON/hash 稳定。
3. 真实 QGIS 3.44.14 / PyQGIS：插件生命周期、图层有效、真实核心调用、Layout PDF 导出。
4. 独立 PDF：文本回读、页数、渲染、人工目视。
5. Quimer 人工：可见 Dock 布局、真实鼠标/键盘操作数、QGIS 地图视觉、3–5 分钟演示与比赛提交。

## 11. 明确不做

- 不连接运营商数据库、云模型、在线底图或外部 API；
- 不声称公开道路是现实管道或光缆；
- 不计算真实造价、施工工艺、光功率预算或工程安全间距；
- 不生成可直接施工/签章的图纸；
- 不用自动化系统时长冒充人工对照；
- 不发布数据、代码、视频、报名材料，不推送分支或创建 PR。
