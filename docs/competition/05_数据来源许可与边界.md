## 2. 分类

| 对象 | 分类 | 是否可称为现实通信资产 |
|---|---|---|
| 道路、建筑、水体、用地、铁路 | 公开现实背景的派生子集 | 否 |
| 候选通道坐标 | 沿公开道路派生的几何 | 否 |
| A/B 站点 | 合成 | 否 |
| 通道 ID、类型、容量、占用、状态、成本系数 | 合成 | 否 |
| 路线、冲突、BOM、图纸 | 本样例的派生输出 | 否 |

候选网络包含两条边不重合的公开道路几何走廊，共 79 个节点、79 条边；QGIS 使用同一批边生成的纯 LineString 视图，避免混合几何类型歧义。这里的“已有管道”“新建”“容量不足”只是规则演示字段，不能反推现实地下管线、站址、权属、运营商、容量或造价。

## 3. 许可与署名

- 必须保留：`© OpenStreetMap contributors`；
- 数据许可：Open Database License 1.0（ODbL）；
- `data/competition/NOTICE.md` 与图纸底部保留署名和边界声明；
- 对外发布数据库或实质性派生数据库前，由提交人复核当时有效的 OSMF 署名指南、ODbL share-alike 与 notice 位置；
- 插件中捆绑的 NetworkX 许可证随分发包保留。

本仓库内的许可记录是工程证据，不构成法律意见。

## 4. 隐私与敏感性

staging 审计未发现被禁止的敏感标签键。派生子集不保留联系方式或现实通信设施标签，标签仅显示合成 ID。即便如此，对外发布前仍应人工复核地图范围、截图、日志和新增数据，防止未来修改引入敏感信息。

## 5. 几何处理

脚本仅保留与样例路线范围相关的背景子集。对 Polygon/MultiPolygon 环执行闭合校验；只有首尾不一致时才在派生副本末尾补回首点，并记录 `geometry_repair` 和每层修复数。当前冻结输入的修复数均为 0。QGIS 开发阶段出现的 LinearRing 错误来自 Layout 地图项零尺寸设置范围的时序，不是通过篡改源数据掩盖。

## 6. 禁止用途

不得将本数据包或输出用于：

- 现实通信线路施工、签章、报审、概预算或采购；
- 判断运营商资产、地下管线、真实机房/基站位置或剩余容量；
- 现场开挖、权属、安全间距、光功率或工程合规决策；
- 把合成属性包装为来自 OpenStreetMap 或运营商的事实。
