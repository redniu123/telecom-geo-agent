## 2. 本阶段成功标准

P1 只解决“场景太简陋”问题，不建设完整通信工程平台。

成功结果应为：

```text
真实或脱敏的小范围道路/管道几何
→ 导入适配器转换成统一内部数据
→ 选择两个授权站点
→ 第一次路线经过一个容量不足或不可用段
→ Validator 发现问题
→ Repair 后走现实几何上的替代路线
→ 输出现实场景 GeoJSON、BOM、校核和日志
→ QGIS 中能看到道路、建筑、节点、问题段和前后两条路线
```

P1 仍然不是生产工程设计，不计算真实造价，不自动发布数据，不连接生产数据库。

## 5. 数据包最低要求

推荐范围：

```text
1～3 平方公里
或起终点距离约 1～3 公里
```

推荐规模：

```text
站点：2～10 个
连接节点/人孔：20～100 个
管道或候选线路段：30～200 条
至少两条 A-B 可行通路
至少一个可解释的问题段
```

最低可接受图层：

| 图层 | 必需 | 几何 | 最低用途 |
|---|---:|---|---|
| `sites` | 是 | Point | 机房、基站、光交箱等起终点 |
| `network_nodes` | 是 | Point | 人孔、手孔、杆或连接点 |
| `duct_segments` | 是 | LineString | 已有管道、杆路或明确候选通道 |
| `roads` | 强烈推荐 | LineString | 现实背景和新建候选通道 |
| `buildings` | 推荐 | Polygon | 现实背景和避让 |
| `water` | 可选 | Polygon/LineString | 水体背景或约束 |
| `restricted_areas` | 可选 | Polygon | 铁路、禁区、不可施工区 |
| `existing_cables` | 可选 | LineString/表 | 已有光缆展示和后续扩展 |

## 6. 优先数据格式

优先顺序：

```text

2. GeoJSON
3. Shapefile 完整压缩包

```

若为 Shapefile，必须同时有 `.shp`、`.shx`、`.dbf`、`.prj`，中文字段最好有 `.cpg`。

Codex 不得仅凭扩展名猜测编码、坐标系或字段语义。

## 8. 原始数据保护规则

- 原始文件只读保存，不在原文件上编辑；
- 计算并记录每个原始文件的 SHA-256；
- 默认把 `data/source_private/` 加入 `.gitignore`；
- 不把真实机房名称、详细地址、联系人、电话、设备序列号、账号、告警或安全配置写入公开输出；
- 未获得公开授权时，只提交转换代码和脱敏样例，不提交原始数据；
- 不把内部数据上传到外部转换网站或未经批准的模型服务；
- 截图前检查标签、属性表和路径是否泄露敏感信息；
- 数据来源、真实/脱敏/合成边界必须写入 `source_manifest.json` 和 README。

## 11. 容量模型升级

P0 的：

```text
capacity_cores
used_cores
```

只用于五节点 Demo，不代表真实管道物理容量。

P1 优先使用：

```text
subduct_total
subduct_used
free_subduct_count
```

或数据提供方的实际物理容量单位。

一根 24 芯光缆的 `fiber_cores=24` 是光缆属性，不能默认等价为占用 24 个管道容量单位。P1 最小规则可配置为：

```text
新敷设一根光缆需要 1 个可用子管
free_subduct_count >= 1 → 可用
free_subduct_count == 0 → forbid_asset
```

若只有 `capacity_status=available/full/unknown`，按状态校核；`unknown` 不得自动视为可用。

若数据只有已有光缆的纤芯容量，应标记为“光纤资源容量”，不要冒充“管道可敷设容量”。

  "base_dataset": "demo_real",
  "start_site_id": "A",
  "end_site_id": "B",

## 13. 拓扑处理

优先使用数据提供方的 `from_node`、`to_node` 和稳定 ID。

如果没有节点关系：

1. 先确认 CRS 和米制容差；
2. 只在明确容差内吸附端点；
3. 生成稳定节点 ID；
4. 记录每次吸附距离和推导来源；
5. 输出断点、重复边、孤立分量报告；
6. 不跨越明显空间间隔强行连线。

路线段反向经过时必须反转坐标顺序，最终 LineString 必须连续。

## 14. CRS 和长度

- 原始 CRS 必须明确；
- 不直接把 EPSG:4326 的度当作米；
- 长度计算使用数据提供方确认的米制投影，或可靠的椭球测量；
- 保留 `source_length_m` 和 `calculated_length_m`；
- 两者差异超过配置容差时报告；
- 不未经批准覆盖原始长度；
- 若混合 WGS84 与 GCJ-02/BD-09，必须停止并先统一坐标基准；
- 输出 GeoJSON 可以使用 WGS84，但路由成本中的米制长度必须来自正确测量。

## 20. 停止条件

出现以下任一情况，停止 P1 并保留 P0：

- 无法确认数据使用授权；
- CRS/坐标体系无法确认；
- 没有可靠拓扑或替代路径；
- 容量语义无法确认；
- 必须接生产数据库才能运行；
- 需要公开敏感通信设施位置；
- 为适配真实数据必须破坏 P0 冻结接口或原测试；
- QGIS 视觉对齐失败且无法解释；
- 数据规模使当前方案无法在可接受时间运行。

停止时报告真实原因，不用合成 PASS 掩盖问题。
