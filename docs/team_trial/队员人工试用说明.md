# TelecomGeoAgent 0.5.0 队员人工试用说明

> 试用对象：项目队员、测试人员和评审人员
>
> 推荐环境：Windows 10/11 + QGIS 3.44 LTR
>
> 已实测环境：Python 3.11.4，QGIS 3.44.14-Solothurn
>
> 试用包：`telecom_geo_agent-0.5.0-team-trial.zip`

## 1. 先看结论

队员只需拿到外层试用包，解压后在 QGIS 中安装里面的 `telecom_geo_agent-0.5.0.zip`。插件、NetworkX 运行时、30 条主试用任务、10 条迁移任务、100 条压力任务、地图背景、合成通信设施及数据清单都已打包，不需要另外安装 Python、下载数据、填 API Key 或连接在线服务。

这是竞赛级离线原型，不是现网设计系统。真实公开部分只有 OpenStreetMap 的道路、建筑、水体、用地和铁路背景；站点身份、候选通道身份、子管容量与占用、成本、任务和 BOM 都是明确标注的合成竞赛属性。产物均不能用于施工、签章、概预算、招标或竣工验收。

## 3. 下载后先校验

试用包同目录会有 `telecom_geo_agent-0.5.0-team-trial.sha256`。在 PowerShell 中运行：

```powershell
Get-FileHash -Algorithm SHA256 .\telecom_geo_agent-0.5.0-team-trial.zip
Get-Content .\telecom_geo_agent-0.5.0-team-trial.sha256
```

两处哈希必须一致。解压后，内层插件 ZIP 的固定校验值应为：

```text
DC5B51AA56A8E19CE8143EE255101A49EBD4BCB88F4EFAD7A16F0899725A7F5E
```

如果不一致，不要继续安装；重新获取试用包并保留当前文件作为问题证据。

## 4. 安装前准备

1. 推荐使用 QGIS 3.44 LTR；本次实测为 3.44.14-Solothurn。插件声明支持 3.28—3.99，但其他版本属于需要队员补充的兼容性实测。
2. 保存当前 QGIS 工程，最好新建一个空白测试工程或独立用户配置。
3. 记录 Windows 版本、QGIS 版本和显示缩放比例（100%/125%/150%）。
4. 关闭与本插件同名的旧版插件。不要删除队员原有图层或强制结束 QGIS。

## 5. 安装插件

1. 打开 QGIS。
2. 进入“插件 → 管理并安装插件 → 从 ZIP 安装”。
3. 选择 `01_安装插件/telecom_geo_agent-0.5.0.zip`。
4. 安装并启用“通信工程 Agent”。这是实验性插件，QGIS 可能显示实验性提示，版本号应为 `0.5.0`。
5. 插件会在 QGIS 右侧打开“通信工程 Agent” Dock。如果被关闭，可通过“插件 → 通信工程 Agent → 通信工程 Agent”重新打开。

正确的初始状态应为：

- 默认页签是“批量设计”；
- 显示“未选择数据集”；
- 任务路径为空；
- 没有加载本插件图层；
- “我的工程包 · 待接入”是禁用状态。这是真实功能边界，不是安装失败。

## 6. 10 分钟快速试用

### 第一步：加载已准备的内置数据

点击“加载内置样例”。界面应显示数据合同和 SHA-256 校验通过，并显示以下实际数量：

- 网络节点：411；
- 候选边：444；
- 合成汇聚机房：3；
- 合成接入设施：30；
- 公开背景：建筑 2716、用地 50、铁路 10、道路 93、水体 4；
- 数据集 ID：`osm_shanghai_public_background_synthetic_batch_v1`；
- 署名：`© OpenStreetMap contributors; ODbL 1.0`。

### 第二步：导入和确认任务

1. 点击“导入并校验”，应读取 30 条任务。
2. 点击“预览任务并生成确认指纹”。
3. 核对 10 个高优先级、10 个中优先级、10 个低优先级，以及每任务最多改路 1 次。

### 第三步：运行批量设计

点击“确认并运行批量设计”。等待终态数量出现，必须为：

| 终态 | 数量 |
|---|---:|
| 直接成功 | 19 |
| 绕行成功 | 9 |
| 待人工复核 | 1（T029） |
| 明确失败 | 1（T030） |

T029 和 T030 不应生成 BOM，也不应预占合成子管资源。不要把它们手工改成 PASS。

### 第四步：复核一条跨任务冲突

1. 选择 T002，地图应定位到该任务。
2. 业务详情应说明 T001 先占用了 `BC-0091`，T002 的候选路线因合成子管余量不足而触发一次绕行。
3. 展开“技术证据”，应看到 `R_SUBDUCT_CAPACITY`、`BC-0091`、T001 和前后资源值。
4. 切换“约束前候选路线”和“最终 PASS 路线”，地图应真实变化。

### 第五步：导出

点击“导出图册与 GeoPackage”。界面会显示实际输出目录，至少检查：

- `design_book.pdf`：36 页 A3 横版；
- `batch_results.gpkg`：7 个图层；
- GeoPackage 图层数量：任务 30、候选路线 30、最终路线 28、问题 13、资源 444、机房 3、接入设施 30。

导出产物默认位于插件运行目录下，请以界面显示的路径为准。卸载或重装插件前，先把需要保留的 PDF、GeoPackage、CSV、GeoJSON 和日志复制到队员自己的工作目录。

## 7. 完整人工体验检查

快速试用通过后，请补充以下人工检查：

1. 把右侧 Dock 缩窄到约 350 px，确认无横向滚动条，任务、优先级和状态主列仍可见。
2. 在 Windows 125% 或 150% 显示缩放下检查中文按钮、表格、详情和纵向滚动。
3. 分别筛选四种终态，确认任务表和地图同步；“待人工复核”只有 T029，“明确失败”只有 T030。
4. 抽查 PDF 封面、T002、T029、T030、资源页、BOM/异常页和数据边界页，检查中文、比例尺、页码、OSM 署名及“合成通信属性 / 非正式施工图”声明。
5. 在 QGIS 中加载导出的 `batch_results.gpkg`，检查 7 个图层及数量，并对照 PDF 与插件详情。
6. 禁用插件，确认菜单、工具栏、Dock 和插件自有图层被清理，队员自己的图层不受影响。

自动化已覆盖 100%/150% 渲染、窄 Dock 和图层生命周期，但上述检查仍必须由真人在可见 QGIS 窗口中完成。

## 9. 常见问题

### 安装后没有右侧 Dock

先在插件管理器中确认“通信工程 Agent”已启用，再通过插件菜单或工具栏图标打开。若仍失败，记录 QGIS 版本和“视图 → 面板”中是否存在该 Dock。

### 加载内置样例失败

不要修改 ZIP 中的数据来绕过哈希失败。保留错误文本，核对插件 ZIP 的 SHA-256，重新安装本试用包内的原文件。

### “我的工程包”不可点

这是 0.5.0 的已知边界：外部工程包的插件 GUI 适配尚未实现。本轮请只测试“加载内置样例”，不要把禁用状态报告为数据缺失。

### 导出时间较长或文件被占用

先等待 QGIS 完成导出，不要在产物仍作为图层打开时手动删除文件。可先在 QGIS 中移除本插件导出的测试图层或禁用插件，然后重试。保留原始错误信息，不要用空 PDF、截图或手写 PASS 替代真实导出。
